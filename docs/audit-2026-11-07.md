# GutCheck audit, 2026-11-07 (v0.26.0)

A read-only audit of every surface: the Electron app (main, preload, renderer), the CLI, the MCP server, the shared engine and service, the scanners and checks, the actions, apply and reports, and the agent, clutter, quality and tests scanners. It also covers repo upkeep (CI, releases, dependencies, docs).

**Baseline.** `npm test`: 224/224 pass. CI and CodeQL are green on `main`. `npm audit`: 0 vulnerabilities. No open PRs or issues. GutCheck scores itself A/100. No `TODO`/`FIXME` markers in the code. Every file is under 400 lines.

**Method.** Five reviewers each took one area, and every claim had to be traced to code or reproduced in a throwaway repo. The top claims were then checked again by hand. **Verified** in the tables means reproduced or traced line by line in this audit. **Code** means confirmed by reading the code only. **Plausible** means a runtime check is still needed.

**Headline.** The core safety design holds:
- Plan tokens are single-use and expire.
- Every git/gh call passes arguments as an argv list, not a shell string.
- There is no force-push, history rewrite, visibility change or repo deletion anywhere.
- Electron is hardened: context isolation, sandbox, CSP, a sender check on every IPC handler, no `innerHTML`.
- MCP `--allow-actions` gating holds.

The problems are at the edges:
- Two AGENTS.md rules are broken: repo code can run before approval, and a secret can reach the report.
- Some state goes stale or races between the three surfaces.
- The Fix-all flow can trip over its own ordering.
- Scan logic is duplicated in `main.js` and `engine.js`, and the copies have started to differ.
