# Local multi-repo tools, git GUIs and cleanup tools (as of 2026-11-07)

Method note: repo metadata (stars, licence, pushed_at, latest release) came from the GitHub API via `gh` on 2026-11-07. Feature claims come from READMEs and docs fetched with a summarising fetch tool. Anything not seen is marked UNVERIFIED. `pushed_at` is the last push of any kind, often only Dependabot bumps, so it overstates activity.

## Which tools show status across many repos at once (dirty, ahead/behind, stale branches), and how?

### Takeaway
Only a few tools do it. gita is the clearest: one table, colour-coded branch state plus dirty symbols. myrepos, mani, meta, vcstool and tsrc can run `git status` over many repos, mostly by fanning out the raw command. GitKraken Workspaces is the only GUI with a multi-repo group, but its docs show batch fetch/pull and cross-repo PRs, not a health view. None of them reports stale branches, missing files or policy across repos.

### Cited Findings
- gita: side-by-side status of all registered repos. Branch colour: white = no remote, green = in sync, red = diverged, purple = ahead, yellow = behind. Symbols: `+` staged, `*` unstaged, `?` untracked, `$` stashed. Repos need `gita add` first (`gita add -a` scans a folder recursively). Named groups, `gita shell` for any shell command, `gita super` for any git command, async execution. Python 3.6+. — [gita README](https://github.com/nosarthur/gita)
- gita repo facts: MIT, 1,962 stars, last tag v0.16.8.2, last push 2026-10-21 (API; no GitHub Releases published, tags only). — [GitHub API](https://api.github.com/repos/nosarthur/gita)
- gita user requests: "Number of commits ahead and behind" and a succinct display mode, each with 1 reaction. The repo has few highly-reacted issues. — [#205](https://github.com/nosarthur/gita/issues/205), [#36](https://github.com/nosarthur/gita/issues/36)
- myrepos (`mr`): runs update, commit, push, status, diff etc. across repos listed in `~/.mrconfig`, with `-j` parallel jobs and `mr register` to add the current checkout. Supports git, bzr, Mercurial, Darcs and others. Per-repo command overrides, chained config files. The site lists version 1.20180726 (July 2018) as the latest release. Its licence and platform were not on the page. — [myrepos](https://myrepos.branchable.com/)
- mani: `mani.yaml` holds projects plus custom tasks. `mani init` auto-discovers subdirectories with `.git`, `mani sync` clones all listed repos, `mani exec --all git status --parallel --output table`, `mani list projects`. Linux/Mac, partial Windows. MIT, 789 stars, latest release v0.32.1 (2026-05-15), last push 2026-10-25. Dry-run: not mentioned on the README. — [mani](https://github.com/alajmo/mani), [API](https://api.github.com/repos/alajmo/mani)
- meta (mateodelnorte): a `.meta` JSON file lists child repos. `meta exec "<cmd>"` (with `--parallel`, `--include-only`), `meta git status/clone/update`, `meta project create/import`, npm/yarn wrappers, plugin system (`meta-*`). No built-in subsets of repos, suggested workaround is nested meta repos. — [meta](https://github.com/mateodelnorte/meta)
- meta maintenance: MIT, 2,232 stars, latest release v2.2.25 dated 2021-04-28 (last push 2026-11-05). Issue "Is this project still maintained?" asks the question. — [API](https://api.github.com/repos/mateodelnorte/meta), [#314](https://github.com/mateodelnorte/meta/issues/314)
- mu-repo (fabioz): described as a tool for dealing with multiple git repos. Python package with `mu.py`/`mu.bat`. 368 stars, last release tag mu_repo_1_9_0, last push 2024-02-12, licence reported as NOASSERTION. Command details (`mu st`, `mu pull`) were not on the fetched page, UNVERIFIED. — [mu-repo](https://github.com/fabioz/mu-repo), [API](https://api.github.com/repos/fabioz/mu-repo)
- ghq: organises clones under `~/ghq/<host>/<owner>/<repo>`. Commands `get` (with `-u` to update via ff-only pull), `list`, `rm` (with `--dry-run`), `create`, `migrate`, `root`. It does not document any status command. MIT, 3,805 stars, v1.12.0 released 2026-11-03. — [ghq](https://github.com/x-motemen/ghq), [API](https://api.github.com/repos/x-motemen/ghq)
- vcstool: `vcs import/export/status/log/custom/validate` over `.repos` YAML (path, type, url, version), parallel by default, supports git, hg, svn, bzr. Apache-2.0, 506 stars, last push 2024-07-17, no GitHub releases. Successor/deprecation status UNVERIFIED. — [vcstool](https://github.com/dirk-thomas/vcstool), [API](https://api.github.com/repos/dirk-thomas/vcstool)
- tsrc: a manifest repo with `manifest.yml` (url, dest). `tsrc init`, `tsrc sync` (fetch + fast-forward each repo). `status` and `foreach` exist per the docs site but were not seen. BSD-3-Clause, 214 stars, latest tag v3.0.1, last push 2026-10-26. Python 3.8+. — [tsrc](https://github.com/your-tools/tsrc), [API](https://api.github.com/repos/your-tools/tsrc)
- Others, briefly: `gr` (mixu/gr) is a Node tool, 684 stars, last push 2019-01-15, effectively dormant. — [API](https://api.github.com/repos/mixu/gr). Google `repo` (Android manifest-based multi-repo tool, hosted on googlesource, not GitHub): not researched, UNVERIFIED.
- GitKraken Workspaces: Local (not shareable, no integration needed) or Cloud (shareable, needs a hosting-service integration). Repos can be grouped from a provider, a folder ("Sync with local directory" auto-adds folder repos) or a VS Code `.code-workspace` file. Batch actions: fetch all, pull all, clone, open, locate, remove. For Cloud Workspaces the Launchpad icon shows open PRs across all repos in the workspace. The docs page describes no status/health indicators across repos. Cloud Workspaces, Workspace Insights and Launchpad Team View are unavailable for on-prem serverless/self-hosted deployments. Insights needs gitkraken.dev and supports GitHub.com, Bitbucket.org, GitLab.com, Azure DevOps. Pricing tier not on the page. — [GitKraken Workspaces docs](https://help.gitkraken.com/gitkraken-desktop/workspaces/)
- Tower: Mac and Windows only (Linux not mentioned). Free to start with a 30-day trial of Pro features (Stacked Branches, Custom Workflows, Graphite support, Branch Cleanup, Self-Hosted Repos, Merge Detection). A multi-repo overview/workspace feature was not found on the pages fetched, "Bookmarks" is mentioned only as a sidebar item. — [Tower features](https://www.git-tower.com/features), [Tower workflows help](https://www.git-tower.com/help/mac/workflows/overview)
- GitHub Desktop: switches between repos one window at a time. The top issues are "Linux?" (4,853 reactions) and "Support multiple windows" (228). No multi-repo dashboard seen. MIT, 22,062 stars, release-3.6.10 on 2026-10-30. — [API](https://api.github.com/repos/desktop/desktop), [#1525](https://github.com/desktop/desktop/issues/1525), [#3606](https://github.com/desktop/desktop/issues/3606)
- lazygit: a single-repo terminal UI; README mentions worktrees (`w` in branches view) and no multi-repo features. MIT, 83,706 stars, v0.66.2 (2026-10-16). — [lazygit](https://github.com/jesseduffield/lazygit), [API](https://api.github.com/repos/jesseduffield/lazygit)
- GitButler: Tauri/Rust/Svelte client and a `but` CLI; virtual/parallel and stacked branches, forge integration for GitHub/GitLab/Bitbucket (open/update PRs, list branches, CI status), AI commit/PR text. The README does not mention multi-repo support. 21,943 stars, release/0.23.2 (2026-11-02). Licence is Fair Source (not OSI, converts to MIT after two years per the README; API reports NOASSERTION). — [GitButler](https://github.com/gitbutlerapp/gitbutler), [API](https://api.github.com/repos/gitbutlerapp/gitbutler)

### Inferences
- Status across repos is a thin layer: "dirty/ahead/behind" at best (gita, plus anything wrapping `git status`). Nobody in this group computes a finding such as "no CI", "stale PR" or "unpushed branch with no upstream" across a folder.
- Of the GUIs, only GitKraken has an explicit multi-repo concept, and it ties the useful part (Cloud Workspaces, Launchpad, Insights) to its cloud and paid plans. Treat this as an inference from the docs, pricing was not verified.

## Which can make batch changes across repos (as PRs or directly), and with what safety?

### Takeaway
multi-gitter and git-xargs are the real batch-change tools: clone, run a script, commit, open PRs, with dry-run. The local runners (myrepos, gita, mani, meta, vcstool) apply arbitrary shell commands directly to working trees with little built-in safety. ghq and git maintenance change local state narrowly.

### Cited Findings
- multi-gitter: `run` clones each target repo, runs your script, and if exit code is 0 and files changed, commits to a branch and opens a PR. `print` runs without changes, `status` reports PR state by branch, `merge` and `close` act on PRs. `--dry-run` skips push/PR (script sees `DRY_RUN`). Default concurrency 1, optional interactive confirm per commit, `conflict-strategy` `skip` (default) or `replace` (force-pushes the branch). Targets: org, user, GitLab group, topic, repo list, GitHub code/repo search, regex include/exclude. Platforms: GitHub, GitLab, Gitea, Bitbucket Server, Bitbucket Cloud (beta), Gerrit. `pr-auto-merge`, labels, reviewers, drafts, `api-push` for verified commits (GitHub). — [multi-gitter](https://github.com/lindell/multi-gitter)
- multi-gitter facts: Apache-2.0, 1,250 stars, v0.64.0 released 2026-10-22, last push 2026-11-06 — actively maintained. — [API](https://api.github.com/repos/lindell/multi-gitter)
- git-xargs (Gruntwork): runs a command/script per repo, commits, opens PRs, prints a report. Parallel clones (`--max-concurrent-clones` default 4), PR rate-limit handling and retries. `--dry-run` skips push/PR creation but still reports affected repos (script sees `XARGS_DRY_RUN`). Repo input: `--github-org`, `--repos` file, `--repo`, or stdin; `--skip-archived-repos`. `--skip-pull-requests` commits straight to the branch. Stages all new and modified files, so stray changes get committed. Needs `GITHUB_OAUTH_TOKEN`; GitHub only. Default commit message prefixed `[skip ci]`. — [git-xargs](https://github.com/gruntwork-io/git-xargs)
- git-xargs facts: Apache-2.0, 1,137 stars, latest release v0.1.16 on 2025-03-13; recent commits are Dependabot dependency bumps (latest seen 2026-08-12). Best read as maintenance mode. — [API](https://api.github.com/repos/gruntwork-io/git-xargs), commits via GitHub API
- myrepos, gita, mani, meta, vcstool: arbitrary command fan-out (`mr update`, `gita shell`, `mani exec`, `meta exec`, `vcs custom`). No dry-run or preview described in any of them. myrepos docs mention retries for offline failures; no safety model described. — [myrepos](https://myrepos.branchable.com/), [gita](https://github.com/nosarthur/gita), [mani](https://github.com/alajmo/mani), [meta](https://github.com/mateodelnorte/meta), [vcstool](https://github.com/dirk-thomas/vcstool)
- ghq: `get -u` runs ff-only update; `rm --dry-run` previews deletion of a local repo. — [ghq](https://github.com/x-motemen/ghq)
- GitKraken: fetch-all and pull-all across a workspace (pull behaviour selectable). — [docs](https://help.gitkraken.com/gitkraken-desktop/workspaces/)
- What users ask for, multi-gitter: caching repos ([#235](https://github.com/lindell/multi-gitter/issues/235), 10 reactions), signed commits ([#261](https://github.com/lindell/multi-gitter/issues/261), 8), `--keep` to retain the working directory ([#493](https://github.com/lindell/multi-gitter/issues/493), 6), `--output-format` ([#441](https://github.com/lindell/multi-gitter/issues/441), 3), bulk PR approval ([#295](https://github.com/lindell/multi-gitter/issues/295)).

- What users ask for, ghq: SSH URL matching ([#307](https://github.com/x-motemen/ghq/issues/307), 11), Jujutsu backend ([#519](https://github.com/x-motemen/ghq/issues/519), 6), tilde directories ([#326](https://github.com/x-motemen/ghq/issues/326)), flat directories ([#398](https://github.com/x-motemen/ghq/issues/398)).
- What users ask for, meta: Windows `spawn EINVAL` on current Node ([#334](https://github.com/mateodelnorte/meta/issues/334), 8), persistent subset selection ([#282](https://github.com/mateodelnorte/meta/issues/282), 4), maintenance status ([#314](https://github.com/mateodelnorte/meta/issues/314)).

- Recurring themes across the PR-making tools: signed/verified commits, more forges, machine-readable output, and keeping the working dirs for inspection. Nobody in the top issues asks for repo-health scoring.

### Inferences
- The only batch tools with a plan-then-apply flavour are multi-gitter and git-xargs (dry-run, PR as the review step). Both are driven by a user-written script; they do not propose changes themselves.
- git-xargs staging "all new and modified files" is a notable footgun for unattended use (from its README).

### Gaps
- Dry-run behaviour of mani, meta, mu-repo, tsrc not seen (README summaries did not mention it).
- multi-gitter and git-xargs issue sorting used open issues only, closed ones not checked.

## Do any have a notion of health, policy or recommendations? And what do the cleanup tools do?

### Takeaway
No multi-repo runner or GUI has a health or policy model. The nearest are git maintenance's `is-needed`/thresholds (object-store health only), git-filter-repo's `--analyze` (history size analysis), and Tower's Pro "Branch Cleanup". The cleanup tools are per-repo and focus on branches or history.

### Cited Findings
- git maintenance: tasks `gc`, `commit-graph`, `prefetch`, `loose-objects`, `incremental-repack`, `pack-refs`, `reflog-expire`, `rerere-gc`, `worktree-prune`; strategies none/gc/geometric/incremental. `register` adds the repo to the global `maintenance.repo` list; `start` schedules hourly/daily/weekly via systemd timers (Linux), cron, launchd or schtasks; scheduled runs iterate with `git for-each-repo --config=maintenance.repo`. `is-needed` returns exit 0/1, `--auto` uses per-task thresholds. No summary or log output is documented. It optimises, it does not report health. This is the only git-native "many repos" mechanism. — [git-maintenance docs](https://git-scm.com/docs/git-maintenance)
- scalar: part of the git suite (documented since 2.38). `scalar register` + `run` + `reconfigure --all` + `list` + `diagnose` (zip of logs and repo stats) manage an enlistment list; sets recommended config (e.g. `index.version=4`, `core.untrackedCache`, `commitGraph.changedPaths`), enables background maintenance, sparse checkout on clone. Aimed at large repos. Standalone Microsoft repo `microsoft/scalar` is archival-looking: MIT, 1,543 stars, last release v21.03.185.1 (2021). — [scalar docs](https://git-scm.com/docs/scalar), [API](https://api.github.com/repos/microsoft/scalar)
- git-sweep: `preview` lists branches merged into master, `cleanup` deletes (remote branches mainly) after confirmation, `--force` skips prompt. Python 2.6/2.7-era. MIT, 2,725 stars, tag 0.1.1, last push 2023-10-01. Effectively abandoned. — [git-sweep](https://github.com/arc90/git-sweep), [API](https://api.github.com/repos/arc90/git-sweep)
- git-trim: trims local tracking branches whose upstream is merged or gone, can delete merged remote branches. Detects merge, rebase/ff and squash merges. `--dry-run` supported; separates "stray" branches as unsafe by default. MIT, 547 stars, latest release v0.4.3 (2022-12-23), last push 2026-02-05. Open issue "dry-run attempts to push" ([#206](https://github.com/foriequal0/git-trim/issues/206)) and "new release?" ([#198](https://github.com/foriequal0/git-trim/issues/198)). — [git-trim](https://github.com/foriequal0/git-trim), [API](https://api.github.com/repos/foriequal0/git-trim)
- git-delete-merged-branches (hartwork): GPL-3.0, 920 stars, 7.7.0 released 2026-10-13, actively maintained. Interactive/command-line merged-branch deletion; feature detail not fetched, UNVERIFIED. — [API](https://api.github.com/repos/hartwork/git-delete-merged-branches)
- BFG Repo-Cleaner: removes big blobs and secrets from history (`--strip-blobs-bigger-than 1M --replace-text banned.txt repo.git`), claims 10-720x faster than filter-branch. GPL-3.0, Scala/JVM, 12,201 stars, v1.15.0 released 2025-01-18, last push 2025-01-19. Rewrites history, so pushing it needs a force-push. Dry-run/HEAD-protection not on the fetched page, UNVERIFIED. — [BFG](https://github.com/rtyley/bfg-repo-cleaner), [API](https://api.github.com/repos/rtyley/bfg-repo-cleaner)
- git-filter-repo: Git-recommended replacement for filter-branch (per its README). Path filtering/renaming, message rewriting, Python library; `--analyze` helps decide what to prune; refuses to run outside a fresh clone unless `--force`. Needs Git 2.36+, Python 3.6+. Licence listed as GPL-2.0 and MIT (API says NOASSERTION), 13,492 stars, v2.47.0 (2024-12-04), last push 2026-07-09. Top issues: signing previous commits ([#67](https://github.com/newren/git-filter-repo/issues/67), 17), SHA256 ([#559](https://github.com/newren/git-filter-repo/issues/559)). `--dry-run` not mentioned on the README page (the tool does have the flag in its manual, UNVERIFIED here). — [git-filter-repo](https://github.com/newren/git-filter-repo), [API](https://api.github.com/repos/newren/git-filter-repo)
- Tower: Pro features "Branch Cleanup" and "Merge Detection". — [Tower features](https://www.git-tower.com/features)
- GitKraken: Workspace Insights and Launchpad exist as cross-repo views, but their contents were not verified. — [docs](https://help.gitkraken.com/gitkraken-desktop/workspaces/)

### Inferences
- "Health" in this group means repository performance (git maintenance/scalar) or branch hygiene (sweep/trim/delete-merged). None looks at CI, security settings, missing LICENSE/README, secrets in the tree, dependency drift, or PR staleness across repos.
- Cleanup tools are per-repo; to use them across a folder you need a runner (`mr`, `gita shell`, `mani exec`, `meta exec`) wrapped around them.
- Maintenance status split: active (multi-gitter, ghq, mani, gita, tsrc, lazygit, GitButler, GitHub Desktop, git-delete-merged-branches); maintenance mode (git-xargs, git-trim, BFG, filter-repo release cadence slow); stale or dormant (myrepos last release 2018, meta last release 2021, mu-repo 2024, vcstool 2024, gr 2019, git-sweep 2023, scalar standalone 2021).

### Gaps
- Whether GitKraken Insights/Launchpad or Tower surface any "health" metrics: UNVERIFIED (pages 404 or silent).
- BFG safety features (protected HEAD, no dry-run) and git-delete-merged-branches feature detail not verified.

## Comparison: what this group does and does not do for health-auditing a folder of personal repos

### Takeaway
The group covers: discover/register repos (gita, mani, mr, ghq), fan out git commands, show dirty/ahead/behind (gita best), run script-driven batch edits with PRs (multi-gitter, git-xargs), delete merged branches (sweep/trim), scrub history (BFG, filter-repo), schedule object-store upkeep (git maintenance). It does NOT provide: a single health verdict per repo, checks for CI/PRs/branch protection/dependency or Actions security, secret detection, clutter detection, stale-PR tracking, or a plan, preview, apply flow that proposes its own fixes.

### Cited Findings
- Auto-discovery of a folder: mani (`mani init` finds `.git` dirs), gita (`gita add -a`), ghq (`migrate`/`list`), GitKraken ("Sync with local directory"). Others require manual registration (myrepos `mr register`, meta, vcstool/tsrc manifests). — sources above.
- GitHub-org-scale tools (multi-gitter, git-xargs) target remote orgs/lists and require tokens, not a local folder. — [multi-gitter](https://github.com/lindell/multi-gitter), [git-xargs](https://github.com/gruntwork-io/git-xargs)
- Only read-only/preview-style commands seen: multi-gitter `print`/`status`/`--dry-run`, git-xargs `--dry-run`, git-trim `--dry-run`, git-sweep `preview`, ghq `rm --dry-run`, git maintenance `is-needed`. — sources above.

### Inferences
- A tool that audits a personal folder read-only and emits ranked findings plus a reviewable plan would sit in a gap none of these fills: runners provide transport (the "for each repo" loop), cleanup tools provide single-purpose fixes, and the GUIs (GitKraken) put cross-repo views behind a cloud account.
- Likely baseline expectations from this landscape: parallel execution, group/tag filtering, dry-run, machine-readable (JSON) output (requested in mani #99 and multi-gitter #441), signed commits (multi-gitter #261, git-xargs #93), and a clear maintenance story.

### Gaps
- No user-research data on personal-repo audits specifically; issue trackers are about batch editing and UX, not health.
- Star counts are as of 2026-11-07 via the API; licence for several repos reported as NOASSERTION where a file exists but is not auto-detected.
