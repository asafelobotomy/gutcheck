# GutCheck audit, 2026-11-16 (v0.28.1 + clutter sizes, `bfe65e8`)

A read-only audit of `main`: the scans, the actions and apply, the Electron app, the CLI, the MCP server, the reports, and repo upkeep (CI, releases, GitHub settings, docs). It re-checks every item the [2026-11-09 audit](audit-2026-11-09.md) left open.

**Baseline.**
- `npm test`: 701 pass, 3 skipped (they need git 2.54), 0 fail.
- `npm audit`: 0 vulnerabilities. Three dev dependencies have a patch update waiting.
- CI is green on `main`. No open PRs or issues. No Dependabot or secret-scanning alerts. 11 open CodeQL alerts (U1).
- No `innerHTML`, `eval` or `new Function` in `src/`. Every source file is under 400 lines.

**Method.** Four reviewers each took one area (process execution, actions and apply, trust boundaries, scan correctness). Every claim had to be traced to code or reproduced in throwaway repos under a temp HOME with `GIT_CONFIG_GLOBAL=/dev/null` and a fake `gh`. Nothing touched the network. E2, E3, T1 and K2 were then reproduced again by hand in fresh repos.

Status terms:
- **Verified:** reproduced.
- **Fixed (unreleased):** fixed under `[Unreleased]` in `CHANGELOG.md`, with tests in `test/action-safety.test.js` and `test/quality.test.js`.
- **Code:** traced line by line.
- **Plausible:** needs a runtime check.

**Headline.**

The scan side now holds. Every scan git call goes through `exec.git` or `ctx.safeGit`, and none of the config tricks tried ran a program during a scan. The Electron shell, plan tokens, remote-repo restrictions and Read-only mode also held (see "What held").

The problems are on the action side, which is hardened less than scans:
- Actions rated "safe" still run programs named in the repo's `.git/config`, through a partial-clone fetch (E1) and `diff.external` (E2).
- `core.worktree` lets a "safe" branch switch write files outside the repo (E3).
- Fetch, pull and push obey a repo's `http.*` and `insteadOf` settings (E4).
- A credential in a TODO comment still reaches the report (T1).
- Most P2 items from 2026-11-09 are still open, including MCP self-confirming danger actions (C8), which now reaches repos that are not cloned.

> **Threat model.** As on 2026-11-09: a repo whose `.git` someone else wrote (a clone script, a shared folder, an archive). GitHub never sends `.git/config` in a clone, so E1 to E4 need such a repo.

## What held

- **Scans:** every scan git call goes through `exec.git` or `ctx.safeGit`. A partial clone does not lazy-fetch during a scan, and `diff.external` ran nothing during a scan.
- **Remote repos:** the cache clone builds its URL in code, validates owner and name, re-checks config before fetch and blocks ext, fd and file transports. All 34 non-API action types were refused on remote results; `repoDir` is used wherever files are read.
- **Plans:** server-side, random, single-use, expiring and checked against `known`, with a per-repo busy guard. A failed apply stops that repo's batch.
- **Read-only mode** is checked on every mutating path found.
- **Electron:** every IPC channel passes the sender check, including `uq-tokens:read`. Context isolation, sandbox and the strict CSP are intact; the ES module loads under `script-src 'self'`. uQ tokens are validated (hex colours, bounded numbers, 64 KiB cap). The packaged AppImage does not use `--no-sandbox`.
- **Apply file steps:** realpath-parent checks, `lstat`, exclusive create. No escape found.
- **Reports:** fences cannot be closed, file and tag names are single-quoted, the extension allowlist is in place, and the origin URL has its userinfo stripped.
- **State files:** `seen.json`, `trend.json` and `ignores.json` are written by temp file and rename. A `gh` failure never reads as all clear.
- **Not reviewed in depth:** `src/tests/`, `src/agents.js`, `src/agent-context.js`, and `git submodule status` (reasoned, not run).
