# UI audit, 24 November 2026

A review of every page and dialog in the app against four goals: show state rather than describe it,
avoid long lists, let people act on one thing or many, and make every option, action and process
clear. Each row says what was wrong and what changed.

## Shell

| Area | Before | After |
| --- | --- | --- |
| Header | Ten controls in one row of equal weight; gh sign-in and API quota as text pills; Read-only a bare checkbox. | Three groups (brand, workspace bar, status). gh is a coloured dot, the API quota a small gauge (details in the tooltip), Read-only a switch with a lock and a band under the header while it is on. |
| Totals row | Six boxed stats that only repeated the dashboard. | A slim strip; Errors and Warnings open the overview. |
| Sidebar navigation | Eight full-width bordered buttons, no state. | Icon list in three groups with counts (issue types, secrets to back up, clutter items). |
| Repo list | Name and "3 err 10 warn" text only; the only filter was a text box. | Grade bar (click a grade to filter), quick filters (Errors, PRs, Changes), a severity strip per repo, and icons for PRs, uncommitted and unpushed work. Hidden repos are counted, with Show all. |
| Toasts | Every message vanished after 7 seconds, errors too. | Errors stay for 15 seconds and every toast can be dismissed. |

## Repo page

| Area | Before | After |
| --- | --- | --- |
| Header | Grade letter, score pill and the path. | Score gauge, severity strip, and chips for branch, uncommitted, to push or pull, PRs and CI. |
| Layout | One long page: about 30 findings, then PRs, branches, settings and file buttons (3,600 px on the demo repo). | Tabs (Issues, Pull requests, Branches, Settings, Files) with counts. |
| Issues | Flat list by category, one action per row. | Categories fold (open when they hold errors), a severity filter, tick boxes on fixable issues, Select all, and a bulk bar to fix or ignore the ticked ones together. |
| Pull requests | "checks passing · not reviewed" as plain text. | Status dots for checks, review and conflicts; tick several to squash-merge or close together. |
| Branches | Every branch with four buttons, no filter. | Filter by merged, stale, local only or remote only; tick to delete together (the review warns about unmerged ones). |
| Settings | One line of text ("protection: off · alerts: unknown") above seven buttons. | One row per setting with an On, Off or Unknown status and its button beside it; archiving sits apart as a danger row. |
| Files | "+ LICENSE" buttons only for what was missing. | A tile per template: a tick for what exists, a tick box and Add for what is missing, and Add selected. |

## Workspace views

| View | Before | After |
| --- | --- | --- |
| Dashboard | Sixteen KPI cards in one grid. | Cards grouped into Health, On GitHub, On this machine and Deeper scans; clickable cards show an arrow. Needs attention rows carry severity strips; Health by repo shows twelve bars, then Show more. |
| Workspace overview | Every issue type in one list with repo names joined by commas. | Folds per severity (notes start folded), severity and text filters, repo chips that open the repo, and bulk fix across ticked issue types. |
| Clutter | One long list per repo. | Totals as stats (found, safe, selected), a confidence filter, each repo in a fold with its size, a size bar per item, and a sticky bar for removing everything ticked. |
| Code quality | The limits form always open; one block per repo. | Limits folded with the current values shown as chips; each repo folds with its secret and over-limit counts in the header. |
| Tests | One block per repo. | Each repo folds with test counts, a coverage meter and "no tests" status; repos with warnings start open. |
| Secrets | Status counts as pills, then the full list. | Status filter, Select all, a bulk bar, a linked or unlinked vault chip, and Show more after fifteen files. |
| Baseline | A count and comma-separated repo names per rule. | Rules split into "Not met everywhere" and "Met by every repo", each with a progress bar and repo chips that open the repo. |
| History | Every change ever, in one list with commands inline. | Grouped by day (older days folded), filter to failures or search, commands behind a toggle. |

## Dialogs

| Dialog | Before | After |
| --- | --- | --- |
| Review changes | A list of plans with tick boxes. | A count by risk, Tick all and Untick all, and unticked plans fade. |
| Results | A list in run order. | "N of M succeeded" with a bar, failures first. |
| Fix all wizard | "Your call 2 of 4" only. | A step bar under the title. |

## Not changed

The flows themselves (plan, preview, apply), what each button does, the safety checks and every
label tests and scripts rely on are unchanged. The uQ theme still maps onto the same colour tokens.
