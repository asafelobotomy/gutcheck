# UI audit, 24 November 2026

A review of every page and dialog in the app against four goals: show state rather than describe it,
avoid long lists, let people act on one thing or many, and make every option, action and process
clear. Each row says what was wrong and what changed.

## Shell

| Area | Before | After |
| --- | --- | --- |
| Header | Ten controls in one row of equal weight; gh sign-in and API quota as text pills; Read-only a bare checkbox. | Three groups (brand, workspace bar, status). gh is a coloured dot, the API quota a small gauge (details in the tooltip), Read-only a switch with a lock and a band under the header while it is on. |
| Totals row | Six boxed stats that only repeated the dashboard. | A slim strip; Errors and Warnings open the overview. |
| Sidebar navigation | Eight full-width bordered buttons, no state. | Icon list in three groups with counts (issue types, secrets to back up, clutter items). |
| Repo list | Name and "3 err 10 warn" text only; the only filter was a text box. | Grade bar (click a grade to filter), quick filters (Errors, PRs, Changes), a severity strip per repo, and icons for PRs, uncommitted and unpushed work. Hidden repos are counted, with Show all. |
| Toasts | Every message vanished after 7 seconds, errors too. | Errors stay for 15 seconds and every toast can be dismissed. |

## Repo page

| Area | Before | After |
| --- | --- | --- |
| Header | Grade letter, score pill and the path. | Score gauge, severity strip, and chips for branch, uncommitted, to push or pull, PRs and CI. |
| Layout | One long page: about 30 findings, then PRs, branches, settings and file buttons (3,600 px on the demo repo). | Tabs (Issues, Pull requests, Branches, Settings, Files) with counts. |
| Issues | Flat list by category, one action per row. | Categories fold (open when they hold errors), a severity filter, tick boxes on fixable issues, Select all, and a bulk bar to fix or ignore the ticked ones together. |
| Pull requests | "checks passing · not reviewed" as plain text. | Status dots for checks, review and conflicts; tick several to squash-merge or close together. |
| Branches | Every branch with four buttons, no filter. | Filter by merged, stale, local only or remote only; tick to delete together (the review warns about unmerged ones). |
| Settings | One line of text ("protection: off · alerts: unknown") above seven buttons. | One row per setting with an On, Off or Unknown status and its button beside it; archiving sits apart as a danger row. |
| Files | "+ LICENSE" buttons only for what was missing. | A tile per template: a tick for what exists, a tick box and Add for what is missing, and Add selected. |

| View | Before | After |
| --- | --- | --- |

## Text to icons (second pass)

Every word on screen was checked against one rule: a word becomes an icon only when the icon is
widely understood, the item repeats (on every row, or on every page), and the word has a clear
place to live on. Each icon-only button keeps its words as hidden text and as an `aria-label`
(screen readers, search, tests) and shows a fuller tooltip. Each icon badge keeps its word as
hidden text and tooltip too.

| Where | Was text | Now |
| --- | --- | --- |
| Header | Browse…, Settings | Folder and gear buttons |
| Header | gh: signed in | GitHub mark with a green or red dot (the words stay when not signed in, since they say what to run) |
| Header | Read-only | Lock icon with its switch |
| Repo list | 3 err, 10 warn, 6 PRs, ● changes, ↑2, local only | Error circle, warning triangle, PR, pencil and arrow icons with their counts; a crossed-out cloud for "no GitHub backup" |
| Repo header | Rescan, Fetch & prune, Open folder, Open on GitHub ↗, Copy for LLM | Refresh, download, folder, GitHub and copy buttons. Fix all issues keeps its words: it is the main action. |
| Repo header | clean, 2 to push, 1 to pull, 6 open PRs | Check, arrow and PR icons with counts |
| Issue rows | Open ↗, Ignore… | External-link and crossed-eye buttons. Each fix button keeps its own words: they differ per issue. |
| Issue severity | Triangle for every level | Circle for errors, triangle for warnings, dot for notes, so severity does not rest on colour alone |
| PR rows | Close, Open ↗ | Cross and external-link buttons. Merge… and Ready for review keep their words. |
| Branch rows | Switch, Merge into current…, Open PR…, Delete, Force delete, Delete on GitHub | Swap, merge, PR and bin buttons (red when commits could be lost); each tooltip names the branch |
| Branch badges | current, merged, stale, local only, remote only, PR #4 | Star, merge, clock, laptop and cloud badges; PR icon with the number |
| Files tab | + LICENSE and others | Plus button on each missing file's tile (the tile already names the file) |
| Clutter | Category words (cache, backup, env file…), git-ignored | One icon per category; crossed eye for git-ignored |
| Secrets | Status words, probably a test key, Don't back up… | Status icons (shield-check for backed up, warning for not backed up, refresh for changed, cross for missing), a flask for test keys, crossed-eye button. The status filter above the list still spells each status out. |
| Results dialog | ✓ / ✗ after the repo name | Check or cross badge |
| History | ✓ / ✗ before each entry | The row's own icon (the symbol stays as hidden text) |
| Agents dialog | Copy, Docs | Copy and book buttons |
| Review rules | Show / Hide | Eye / crossed-eye button |
| Rescan buttons on Clutter, Code quality, Tests, Secrets | Rescan | Refresh button |

Kept as words, on purpose: tab names, filter options, the Health/On GitHub group titles, stat
labels, every action that changes something specific (Fix all, Merge…, Back up, Archive repo,
Protect default branch…, Remove selected), the risk labels in the review, Deep scan (no icon says
"also run npm outdated"), and the sidebar views (the sidebar has room, and the words are how
people find the views).

## Not changed

The flows themselves (plan, preview, apply), what each button does, the safety checks and every
label tests and scripts rely on are unchanged. The uQ theme still maps onto the same colour tokens.
