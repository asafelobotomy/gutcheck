# GutCheck security audit, 2026-11-09 (v0.27.1 + unbacked secrets, `da31ccf`)

A read-only security audit of `main` after the unbacked-secrets feature landed. It has three parts:
- **A. Secrets feature:** the new feature, attacked as a malicious repo, a confused vault CLI, a local user and a prompt-injected MCP client.
- **B. Processes and repo changes:** everything that runs a process or changes a repo.
- **C. Trust boundaries:** Electron IPC, the MCP server, "Copy for LLM" reports, redaction and the user's rules.

It also re-checks every open item from the [2026-11-07 audit](audit-2026-11-07.md).

**Baseline.**
- `npm test`: 347/347 pass.
- `npm audit`: 0 vulnerabilities, with or without dev dependencies.
- No `innerHTML`, `eval` or `new Function` in `src/`.
- Every file is under 400 lines.

**Method.** Three reviewers each took one part, and every claim had to be traced to code or reproduced. The reproductions used throwaway repos under a temp HOME, with `GIT_CONFIG_GLOBAL=/dev/null`, a fake `gh` and fake vault CLIs. Nothing touched the network or a real vault. A marker file proves code ran. The P0 code-execution claims were then reproduced again by hand (B1 confirmed).

The Status column uses three terms:
- **Verified:** reproduced.
- **Code:** traced line by line.
- **Plausible:** needs a runtime check.

**Headline.**

The app shell is well hardened:
- context isolation, sandbox and a strict CSP
- a sender check on every IPC handler, including the eight new `secrets:*` channels
- `openExternal` limited to `https://github.com/`
- no string-built DOM
- plans that are server-side, single-use and expiring
- argv-only processes, so there is no shell anywhere

The secrets feature also holds its main promises:
- Contents go only to the vault CLI's stdin.
- Apply sends exactly the previewed bytes.
- MCP cannot write to a vault.

**But the core rule "scans never run repo code" is broken, and so is "nothing force-pushes".** `READONLY_GIT` turns off hooks and fsmonitor only. A cloned repo's own `.git/config` can still name programs that a plain scan runs:
- a clean filter (B1)
- `gpg.program` (B2)
- textconv (B3)

Several actions rated "safe" also obey repo config:
- push can mirror-delete or force-push remote branches (B5)
- fetch can prune every local branch (B8)
- fetch, pull and push can run `ext::`, `sshCommand` and similar programs (B9)
- actions run the repo's own hooks (B10)

Scanned branch names reach option position (B6, B7).

Separately:
- A report command can be turned into command injection by a file name (C1).
- A repo can hide its own security findings and label that as "the owner's" decision (S9, C2).
- Ignores bypass Read-only mode (C3).

> **Threat model.** "A repo you scan" covers anything you cloned, including its `.git/config` once it is on disk (a malicious clone script, a shared folder, an archive, `clone --recursive` into submodules). GitHub never sends `.git/config` in a clone, so B1–B3 and B5–B10 need a repo whose `.git` someone else wrote. AGENTS.md promises safety in exactly that case.

## What held

- **Electron:**
  - Every IPC channel goes through `trusted()`, including the eight `secrets:*` channels.
  - Preload exposes fixed `invoke` wrappers only.
  - Context isolation, sandbox and a strict CSP are on, with no `innerHTML`.
  - `openExternal` takes only `https://github.com/` and exact docs URLs.
  - New windows are denied and navigation is prevented, as are webviews and permission requests.
  - In a jsdom check, `<img onerror>` and `<script>` in repo names, titles and branches rendered as text.
- **Plans:**
  - Plans are stored server-side under a random single-use token that expires.
  - Apply runs exactly the stored steps.
  - Danger plans need the typed name for every token, except over MCP (C8).
- **Processes:**
  - Every process is spawned with argv, never a shell string.
  - The registry has no repo delete, visibility change, force flag or history rewrite. B5–B8 reach those through repo config and ref names, not through action input.
- **Repo writes:**
  - Writes go through `assertInside` and `wx`.
  - `remove` re-checks at the last moment, uses `--literal-pathspecs`, and trashes with `gio trash --`.
  - `commit-all` refuses lines that weren't previewed.
- **Secrets:**
  - Contents go to the vault CLI's stdin only. A fake CLI's log confirmed it.
  - The file is read with `O_NOFOLLOW|O_NONBLOCK`, a 1 MB cap and a sha256 re-check, so apply sends exactly the previewed bytes.
  - Vault binaries inside a repo or the root are refused, PATH is filtered, and the CLI runs with `cwd = home`.
  - MCP is refused at three layers, and `mcpView` strips paths, hashes, targets and `fix.paths`.
  - The record is 0600 and holds hashes and ids only. Vault stdout never reaches the UI.
- **MCP gating:**
  - `--allow-actions` gates plan, apply, ignore and live usage.
  - `resolve()` returns only known repos.
  - `clean-clutter` paths must come from current results, and `gitignore-append` uses an allowlist.
