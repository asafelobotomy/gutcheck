# Community pain points and comparable tools: opportunities for GutCheck (research date 2026-11-10)

Method note: about 20 tool calls. Web search is US-only and snippet-based; HN Algolia queries for backup/AGENTS.md returned 0 hits and the multi-repo query returned only tiny Show HN posts (1-9 points). Reddit, Lobsters and Stack Overflow were not reachable through search, so "how often" is mostly inferred from tool star counts, number of independent tools and incident write-ups, not upvotes. Items GutCheck already does (per docs/sources.md and README) are excluded.

## Comparable tools and standout features GutCheck lacks

### Takeaway
Multi-repo tools win on fast cross-repo status plus "run a command everywhere" and clone-from-manifest; disk cleaners win on safe interactive delete with dry-run/JSON; dashboards (Renovate, Cortex/OpsLevel) win on one-place state plus tracked maturity over time. GutCheck's gaps are mostly: a workspace manifest to restore/clone missing repos, trend/scorecard history, machine-readable output, and fork/identity awareness.

### Cited Findings
- Star counts (GitHub API, 2026-11-10): ghq 3,807; gita 1,962; mani 789; gickup 1,506; kondo 2,585 (last push 2026-04-24); npkill 9,501; OpenSSF Scorecard 5,819; Allstar 1,467; Renovate 23,065; Repolinter 466 and archived (Feb 2026) — queried via api.github.com/repos/{owner}/{repo}, e.g. [npkill](https://github.com/voidcosmos/npkill), [ghq](https://github.com/x-motemen/ghq), [gita](https://github.com/nosarthur/gita), [gickup](https://github.com/cooperspencer/gickup), [mani](https://github.com/alajmo/mani), [repolinter](https://github.com/todogroup/repolinter).
- gita: side-by-side status of many repos (branch, modified/staged/untracked symbols, last commit message), repo groups, and "superman mode" running any git command across all or a subset, async — [gita on PyPI](https://pypi.org/project/gita/0.16.3).
- npkill (most-starred cleaner): lists dirs with size and a last-modified column, multi-select with range selection, regex search, exclude dirs, "older than N days" filter, `--dry-run`, `--json` / `--json-stream` for scripting, warning marker for dirs some apps need. README pitches speed and one-key delete; no user testimonials on page — [npkill README](https://github.com/voidcosmos/npkill).
- Many small "are all my repos clean/pushed?" tools exist (git-scan: missing pushes/pulls, uncommitted, untracked, stashes, dangling branches; repos; gitool; mrh; git-conform; check-projects; git-leave) — evidence of a recurring need, but all are single-machine, shallow — [search result roundup](https://pypi.org/project/git-scan), [gitool](https://pypi.org/project/gitool/1.1.3), [git-conform](https://docs.rs/crate/git-conform/0.2.0), [mrh](https://docs.rs/crate/mrh).
- HN Show HN activity (small): "Fresh: CLI tool for interactively managing the status of multiple Git repos" (2 pts, 2026-01-03, item 46480397); "Bash functions to bulk-maintain Git repos" (2 pts, 2025-11-20, item 45990210); "Multi-Repo Tool" (1 pt, 2025-12-02) — [HN Algolia query](https://hn.algolia.com/api/v1/search?query=multiple%20git%20repos%20status%20tool&tags=story). Low votes: the problem is felt but no breakout winner.
- Renovate: praised mainly for the Dependency Dashboard (one issue showing every pending update, with checkboxes to trigger) and first-class grouping; Dependabot added groups late 2024 narrowing the gap. Renovate docs describe the arc "feel the power" then "this is overwhelming" — [Renovate noise reduction](https://docs.renovatebot.com/noise-reduction/), [GitHub blog: Tame Dependabot](https://github.blog/2024-04-24-tame-dependabot-group-your-updates-slow-the-cadence-keep-security-fast/), [Renovate vs Dependabot 2026 (anecdotal)](https://blog.codercops.com/blog/renovate-vs-dependabot-dependency-updates-2026/).
- Scorecard tools (Cortex, OpsLevel, Backstage Soundcheck/Tech Insights): checks roll up to a maturity level per entity, scoped rubrics per team, scorecards track migrations/standards over time, "catalog-info.yaml in every repo" as the registry — vendor claims, not independent — [Cortex scorecards docs](https://docs.cortex.io/scorecards/create), [OpsLevel checks](https://opslevel.com/resources/check-creation-101-how-checks-work-in-opslevel). Backstage Tech Insights itself: no source found.
- Repolinter archived and Allstar/Safe Settings are org-level: personal-workspace policy-as-code is an unfilled niche (GutCheck already cites this in sources.md).

### Inferences
- Features worth borrowing: (1) a workspace manifest (like mani/ghq/gita config) listing remote URLs so a new machine can `gutcheck restore` clone everything missing, and so "repo on GitHub but not cloned" / "cloned but remote gone" can be reported; (2) `--json`/`--json-stream` and `--dry-run` parity on every CLI command (npkill pattern; GutCheck may already have some, check); (3) groups/tags for repos with per-group baselines; (4) score history/trend per repo (OpsLevel/Cortex "maturity over time"); (5) a "dependency dashboard" view: all open bot PRs across all repos in one list with bulk close/merge.
- "Last-modified age filter + size sort + multi-select" is the praised disk-cleaner UX; GutCheck currently only gives info findings and preview commands for dependency folders (docs/sources.md "Disk space"), so a size-sorted, selectable, workspace-wide reclaim view is a refinement.

### Gaps
- No Reddit/Lobsters/SO threads were retrievable; "what users praise most" for gita/mani/ghq is from READMEs, not user quotes. kondo/cargo-sweep/mr/myrepos/git-repo-manager/meta features were not fetched.

## Forum pain points GutCheck could address

### Takeaway
Strongest verifiable signal is around (1) account-loss/backup fear, (2) wrong git identity across multiple accounts, (3) bot PR noise, (4) forgotten local work across machines. Backup of non-pushed state is well covered by recipes but no tool bundles it per repo.

### Cited Findings
- Account loss / GitHub backup: a Lupine.dev post cites an HN discussion of a maintainer whose GitHub account was disabled and argues for regular off-site backups; notes a plain clone omits issues, PRs, wikis — [Lupine.dev](https://lupine.dev/articles/github-takeout/). Many one-off backup scripts exist (bugh, octarchive, git-sync, Addy Osmani and Deepak Ness posts) — [Addy Osmani](https://addyosmani.com/blog/backing-up-a-github-account/), [octarchive](https://github.com/pojntfx/octarchive). gickup (1.5k stars, active Nov 2026) is the dedicated tool. I could not verify gickup's feature list or the HN thread directly.
- Backing up unpushed work: `git bundle create x.bundle --all` covers refs only, not ignored files, uncommitted changes, hooks or repo config; gitolite tip bundles everything not on a remote by making a temp commit of index+untracked then `git bundle create --all --not --remotes`; stashes need per-stash patch files — [simplified.guide](https://www.simplified.guide/git/bundle-create-restore), [gitolite tips](https://gitolite.com/tips-3.html), [DZone "git backups and no it's not"](https://dzone.com/articles/git-backups-and-no-its-not), [git-bundle-plus](https://pypi.org/project/git-bundle-plus/). Restic recommendation for workspaces: not found in sources.
- Multiple identities: common blog topic; fix is `includeIf "gitdir:"`, or (Git 2.36+) `includeIf "hasconfig:remote.*.url:"`, separate SSH keys per account (GitHub refuses one key on two accounts), and a pre-commit hook checking email; one write-up of two weeks of commits under the wrong email — [OneUptime 2026-01-24](https://oneuptime.com/blog/post/2026-01-24-git-config-multiple-accounts/markdown), [DEV: wrong git email 2 weeks](https://dev.to/sandeepbansod/i-used-the-wrong-git-email-for-2-weeks-and-no-one-noticed-1b3p), [GitHub: troubleshooting commits](https://docs.github.com/en/pull-requests/how-tos/commit-changes/troubleshooting-commits). Prevalence not measured.
- Dependabot noise: GitHub's own blog says defaults flood repos; recommended groups + cooldown (GutCheck already checks) — [GitHub blog](https://github.blog/2024-04-24-tame-dependabot-group-your-updates-slow-the-cadence-keep-security-fast/).
- Forgotten work across repos/machines: no HN thread with traction found; evidence is the 7+ tools above and an HN Show HN trickle.
- Not researched/no source: stale forks, notification overload, dotfiles, build-dir disk usage threads (npkill's 9.5k stars is the only proxy).

### Inferences (concrete GutCheck ideas)
- Identity check: per repo, compare effective `user.email` (after includeIf) with the email of the last N commits and with the remote's owner (account/org); warn on mismatch; flag a repo whose remote owner differs from the global identity with no `includeIf`/`hasconfig` rule. Read-only, fits "Workspace git config" checks. The README/sources show only global `user.email` presence is checked today.
- "Rescue bundle" action: plan/preview a `git bundle create --all --not --remotes` plus stash patches plus untracked-file list per repo into a chosen folder; verify with `git bundle verify`. Matches GutCheck's plan/preview/apply model and extends the secrets-backup idea to unpushed work. Dry-run lists what exists only locally (unpushed commits, stashes, untracked non-ignored files, repos with no remote at all).
- "No remote at all / remote is not GitHub" finding: repos whose only copy is local.
- Offsite-backup freshness: report "last backup age" per repo if user configures a backup target (gickup/restic/bundle dir).
- Stale forks: fork behind upstream by N commits, via `gh repo view --json isFork,parent` — plausible, but no forum evidence collected.

### Gaps
- Upvote/thread-count quantification for all of these; Reddit and Lobsters not accessed.

## AI coding agents and repo hygiene (2025-2026)

### Takeaway
Documented risks cluster on repo-controlled config that executes or auto-approves things: `.mcp.json` servers auto-enabled, hooks/env in committed settings, and skill/context files carrying hidden instructions. GutCheck already covers literal credentials in `.mcp.json` and committed `settings.local.json`; the larger gaps are trust-widening flags, commands in MCP/hook entries, hidden Unicode in agent files, and agent-created worktree/branch debris.

### Cited Findings
- CVE-2026-21852 (reported by Check Point, Jan 2026 per secondary write-up): `enableAllProjectMcpServers: true` in `.claude/settings.json` auto-approved every server in a project's `.mcp.json`, including ones added by any committer; also `ANTHROPIC_BASE_URL` in project config could redirect API traffic/keys. Secondary source, CVE text not checked at NVD — [DEV Community write-up](https://dev.to/sattyamjjain/cve-2026-21852-how-enableallprojectmcpservers-leaks-your-entire-source-code-5ddc), [NeuralTrust](https://neuraltrust.ai/blog/claude-code-cursor-mcp-security). Same write-up lists scanner ideas: invisible Unicode in tool descriptions, shell injection in server commands (`sh -c`, pipes), `headersHelper` arbitrary command execution, tool "rug pulls".
- A GitHub Action before v1.0.74 read `.mcp.json` from a PR branch (CVE-2026-47751 per search summary; unverified at NVD). Mitigations in sources: treat `.mcp.json` changes as code in review, put them under CODEOWNERS, never persistently approve untrusted servers — [search summary of vendor posts](https://heyuan110.com/posts/ai/2026-03-10-mcp-security-2026). "30 CVEs in 60 days" and "5.5% of public servers poisoned" are single-vendor figures, unverified.
- Official Claude Code settings docs (read directly): committed `.claude/settings.json` carries permissions, hooks, plugins, env; `permissions.allow`, `additionalDirectories`, `extraKnownMarketplaces`, most `env` wait for folder trust; `deny`/`ask` apply immediately; `permissions.defaultMode` `auto`/`bypassPermissions` do not take effect from project/local files (before v2.1.257 `bypassPermissions` did take effect from any file); a tracked `settings.local.json` needs the trust step — [Claude Code settings](https://code.claude.com/docs/en/settings). Implication: a committed `bypassPermissions` is only dangerous for users on old versions; a committed `hooks` entry or `extraKnownMarketplaces` is repo-controlled code/plugin source.
- Skills/context poisoning: CSA research note names SKILL.md, CLAUDE.md, AGENTS.md as primary delivery for context poisoning, including invisible Unicode; USENIX Security 2026 study (via OWASP AST01) scanned 98,380 skills, 157 confirmed malicious; a Jan 2026 study reports >26% of public skills with at least one vulnerability (secondhand via Mondoo); OWASP lists skills writing backdoor instructions to persistent identity files — [CSA note](https://labs.cloudsecurityalliance.org/research/csa-research-note-skill-md-agent-context-poisoning-20260506), [OWASP AST01](https://owasp.github.io/www-project-agentic-skills-top-10/ast01) (redirect target; page not read), [Mondoo](https://mondoo.com/blog/agent-skills-real-power-real-risk), [arXiv 2602.14211](https://arxiv.org/pdf/2602.14211).
- Agent clutter: Claude Code issues report stale worktrees never cleaned across sessions (#26725), orphaned worktrees on Ctrl+C with `--worktree --tmux` (#27169), locked agent worktrees whose PID died (#57765, suggests PID-aware prune), VS Code extension worktrees never auto-cleaned (#31488), leftover `.git/worktrees` entries and stale `extensions.worktreeConfig` git config (#45645). A docs issue says v2.1.76 added auto cleanup for interrupted parallel runs (closed 2026-04-02; unconfirmed). Worktrees live under `<repo>/.claude/worktrees/` per most sources — [#26725](https://github.com/anthropics/claude-code/issues/26725), [#31488](https://github.com/anthropics/claude-code/issues/31488), [claudeissues.com index](https://claudeissues.com/issue/57765-agent-worktrees-with-isolation-worktree-not-cleaned-up-when-calling-session-ends), third-party cleaner [stalewood](https://github.com/retif/stalewood).
- Cleanup danger incident: Mergify author told Claude Code "go ahead" to clean worktrees; agent looped `git worktree remove --force` and deleted ~29 worktrees with uncommitted changes (branches survived) — [Mergify blog](https://mergify.com/blog/the-day-my-ai-agent-deleted-29-git-worktrees).
- Branch hygiene guidance: give each agent branch one outcome (merge/delete/keep/prune), check for uncommitted work in worktrees and open PRs before deleting, keep transcripts separate from workspaces — [Junction Panel](https://junctionpanel.dev/blog/branch-cleanup-after-agent-runs/) (vendor blog).
- Parallel-agent adoption signals on HN: "Optio: orchestrate AI coding agents in K8s" 88 pts/60 comments (2026-03-25); several worktree CLI Show HNs with 1-2 pts — [HN Algolia](https://hn.algolia.com/api/v1/search?query=multiple%20git%20repos%20status%20tool&tags=story).

### Inferences (concrete GutCheck ideas, none currently in docs/sources.md)
- New agent-config checks: committed `enableAllProjectMcpServers: true` / `enabledMcpjsonServers` (error: widens trust to any committer); committed `env.ANTHROPIC_BASE_URL` or other base-URL/proxy override (error); committed `apiKeyHelper`/`headersHelper`/`hooks` commands (info/warn, show only a shape and hash as GutCheck does for permissions); `.mcp.json` stdio servers using `sh -c`, `curl|sh`, `npx -y` unpinned packages (warn); remote MCP URLs over `http://`; `.mcp.json`, `.claude/`, `.cursor/rules`, AGENTS.md absent from CODEOWNERS on repos that have CODEOWNERS; `extraKnownMarketplaces` pointing at non-official sources.
- Invisible-Unicode / bidi / HTML-comment scan of CLAUDE.md, AGENTS.md, SKILL.md, `.cursor/rules`: GutCheck already escapes such characters in displayed names; apply detection to content. Report counts and file names only, never content.
- Agent-debris check: `.claude/worktrees/*` with no live PID/lock, worktrees whose branch is merged, `git config extensions.worktreeConfig` left set with no worktrees; agent scratch folders and transcripts inside the repo not gitignored. The "prunable worktrees" check exists but is gitdir-based; the extra value is "agent-created, merged, clean = safe to remove" versus "has uncommitted work = never --force". Fix steps should refuse `--force` where status is dirty (the Mergify lesson) and be per-worktree, never a loop.
- Also: flag repos where AGENTS.md exists but Cursor/Copilot/Gemini rules are stale duplicates (partly covered already).

### Gaps
- No direct source for Cursor rules security, Codex config (`.codex/config.toml` project trust) or Copilot agent repo-config risks beyond one secondary article on Codex ([codex.danielvaughan.com](https://codex.danielvaughan.com/2026/04/13/mcp-security-codex-cli-cve-config-hardening-trust-boundaries/), not fetched). CVE numbers not verified at NVD. agents.md site and Anthropic memory docs were not re-fetched (sources.md already cites them).

## Scheduled/background maintenance UX

### Takeaway
No retrievable community evidence on this; GutCheck already has tray, schedule, "new since last scan" and notifications.

### Cited Findings
- Renovate's own docs describe the delight-then-overwhelm arc with automated updates, supporting "notify only on new/regressed, batch weekly" — [Renovate noise reduction](https://docs.renovatebot.com/noise-reduction/).

### Inferences
- Possible refinements: a weekly digest (single notification or markdown file with deltas and trend), snooze per finding with expiry (ignore-with-reason expiry date), and quiet hours. Unsupported by sources found.

### Gaps
- Nothing found on tray apps/digests user preferences; not researched beyond one query.
